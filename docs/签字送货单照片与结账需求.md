## 建议操作流程

确认出库并保存送货单 → 打印并送货 → 客户在纸质单据签字 → 在原单据拍照或从相册上传 → 人工核对清晰度、签字和单号 → 客户对账时选单导出照片 → 收款后登记并关联单据。

照片应关联稳定的客户ID与送货单ID，单号、日期、客户及金额作为单据快照保留，不能只靠文件名对应。若只有现存签字纸单而系统无对应业务单，提供待关联凭证登记；上传照片不得自行创建或重复扣减出库库存。

- 出库成功页和送货单详情：拍签字单、相册上传、查看原图。

## 保存与核对规则

1. 原图上传服务端持久存储；缩略图用于列表，放大与导出使用原图。保存原文件，旋转、压缩或隐私元数据清理如需实施应产生衍生版本，不静默替换原图。
2. 上传中、上传失败、已上传待核对、已核对分开显示。仅上传不代表图片真的包含签字，也不代表对方已经认可。
3. 服务端保存成功返回附件ID和关联结果，客户端确认后才提示已保存；刷新后必须能重新读取。不要将本机临时路径当作永久图片地址。
4. 网络失败保留待上传内容并显示重试；评估iOS重启后的草稿恢复。重试幂等，避免同一照片重复挂单；这是附件重试，不是自动排队扣库存。
5. 以照片可读性为优先；提醒拍全纸张、单号、数量金额与签字，允许多张补拍。OCR以后可作辅助，不能自动判定签字有效或替代人工核对。
6. 更换照片保留旧版本和原因；客户改名、修改档案或重打单据不能改变原凭证关联。已结单不自动清理照片；保存期限和删除流程另行确认。
7. 备份包含原图、附件索引、单据关联和校验值，恢复后能查能导出；只有数据库数字的备份不算凭证完整备份。
8. 不把签字、地址、电话、金额图片做成可猜测的公开链接；复用现有受保护访问机制，不因此新增用户登录/角色体系。

## 凭证与收款必须分开

凭证状态：缺照片 / 待上传 / 已上传待核对 / 已核对；收款状态：未收 / 部分收款 / 已结清。照片核对不能自动确认已收款。

客户对账前突出缺凭证清单。是否强制阻止发送无凭证对账单可另定，但不得因为缺照片阻止如实登记已经收到的钱。一次收款可关联多单、一单可分次收款，仍须保留金额分配和剩余应收。

拍照及相册权限拒绝可恢复；大图、旋转图、多页照片仍可读；断网重试不丢图不重复；不能挂错客户或单据；刷新和重启能读取已存原图；导出原图和单据逐一对应；客户更名不破坏历史；已结单仍可查凭证；备份恢复照片与关联一致；上传、核对或删除凭证不改变库存或收款余额。

### 已确认的纸板采购计价规则

- 分别保存订购张数、计费张数、赠送张数、送货张数、实际收货张数及合格数量；订购量不自动等于本次实收或计费量。
- 正常无短收时，实收包含收费纸板和赠送纸板；赠送的合格纸板进入库存，但不增加计费面积或货款。拒收、破损和待检单独处理，不以送货单数量自动全部记作可用。
- 同一规格的理论计费面积=单张长度（米）×单张宽度（米）×确认的计费张数；纸板货款=确认的计费面积×每平方米单价。供应商单据记载面积与理论面积同时保留并核对，尺寸精度、面积取舍与金额舍入规则待确认，不静默改供应商金额。
- 本次确认针对纸板货款；运费、税费如有应独立记录，不能把赠送数量计入收费面积。
- 示例仅用于说明和隔离测试：单张面积1平方米，计费1000张，赠送4张，实收且合格1004张，每平方米2元，则增加合格库存1004张，计费面积1000平方米，纸板货款2000元；不增加为2008元。
- 界面同时显示计费张数、赠送张数、实收张数、计费平方米、平方米单价、货款。供应商对账采用计费金额，领料使用实际合格可用量。赠送不收费不等于已付款，付款仍须单独登记。
- 验收覆盖零赠送、赠送、部分到货、短收破损、重复提交、退货更正；实际多到不能全部自动判为赠送，须按本次单据确认收费与赠送拆分。退货金额以原收费和赠送记录为依据，不能把免费赠送张数自动变成应退货款。
