## 账号与权限

管理员初始登录资料在本机 `release/team-owner-access.txt`，该文件不纳入 Git，也不上传到公共目录。首次登录后在“我的 → 团队与账号”修改密码，为同事创建独立账号。

| 角色 | 查看共享数据 | 新增商品、客户、供应商、订单、出入库 | 编辑、删除、账务及结清 | 账号管理及审计 |
| --- | --- | --- | --- | --- |
| 管理员 | 是 | 是 | 是 | 是 |
| 操作员 | 是 | 是（客户和供应商初始欠款须为零） | 否 | 否 |
| 只读 | 是 | 否 | 否 | 否 |

禁用成员、修改角色或重置密码会立即撤销该成员服务端会话。不能禁用最后一个管理员。用户可修改自己的密码。会话有效期 12 小时，服务器重启后需重新登录。
所有账号属于同一个共享仓库，此版不包含多个互相隔离的仓库。旧版 App 的匿名业务请求返回 401；安装共享版或打开网页入口后登录。下载和更新接口保留公开访问。

## 同步与写入

- 页面在前台每 4 秒查询服务器版本，有变更则刷新商品、库存、客户、供应商、订单、账本和出入库列表；切回前台也会查询。编辑表单不会被轮询覆盖。
- 业务请求只向固定 HTTPS 域名发送认证令牌。登录、退出及切换账号会清理缓存并重新加载页面。
- 管理员编辑资料时使用读取详情时的版本；版本冲突返回 409，拒绝覆盖。需要刷新页面后重新核对并提交。
- 写入携带提交编号与版本号，同一用户相同编号与相同内容的重试返回原结果，七天内不会再次执行。编号相同但内容不同返回冲突。
- 接口同步执行，库存变更、全局版本、成功操作审计和重试凭据写入同一个 `data.json`，采用临时文件、fsync 和原子替换。写入失败回滚内存，不清空原文件。
- 网络失败时明确显示结果尚未确认，保留当前页面表单，原内容重试复用提交编号。此版不提供后台离线上传队列；未提交表单不会跨关闭 App 自动恢复。
- 共享只支持当前单 Node 服务进程，不能直接扩成 PM2 多实例共同写同一 JSON 文件。原有业务数据和字段保留。

## 运维与验证

正式环境备份：`/var/backups/shuguang-team-20260912-01`。发布时停止服务后备份原数据，启动后验证数据 SHA-256 未变；没有向正式库存或账本写测试记录。
后端源码现在归档于 `backend/`。账号密码使用 scrypt 加盐摘要，账号文件权限 600；数据库、账号文件不放入公共目录。

运行测试：

```powershell
npm.cmd ci --prefix backend
npm.cmd test --prefix backend
npm.cmd run build:h5
node tests/team-browser.cjs
$env:TEAM_BROWSER='webkit'
node tests/team-browser.cjs
```

接口测试使用临时数据，覆盖登录、权限、重复提交、两客户端同时出库、库存不足、修改失败回滚、文件写入失败回滚、禁用账号、修改密码和重启后数据保留。
浏览器测试使用独立服务和临时数据库，覆盖两会话共享商品自动刷新、登录和团队页面。公网只验证登录、只读业务接口、退出及 IPA 下载哈希，不写测试业务数据。
热更新使用 `scripts/package-hotupdate.py`（Python zipfile，Deflate，根目录 index.html，ASCII 文件名，解压完整性检查）。不要把旧 `www` 目录直接发布覆盖此次 `dist` 产物。
