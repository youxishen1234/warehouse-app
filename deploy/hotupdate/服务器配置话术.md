# 曙光 App 热更新服务器配置指南（可直接发给服务器管理员）

## 一、基本信息

- 服务器 IP：`152.136.100.200`
- 服务端口：`4000`（后端服务已在此端口运行）
- 协议：HTTP（不需要 HTTPS/SSL 证书）
- App 端热更新地址：`http://152.136.100.200:4000`

## 二、需要你做的事情

### 1. 确保后端服务在 4000 端口正常运行

```bash
# 检查 4000 端口是否在监听
netstat -tlnp | grep 4000
# 或
curl -I http://127.0.0.1:4000
```

如果服务没启动，启动你的后端服务（Node.js / Java / Python 等，按你原来的方式启动）。

### 2. 创建热更新文件存放目录

在你的后端服务的静态文件目录下，创建以下结构：

```
静态根目录/
├── api/
│   └── appupdate/          # 热更新 API（如果后端已实现则跳过）
├── appupdate/               # 热更新包存放目录
│   ├── manifest.json        # 热更新清单（版本号 + 包地址）
│   └── bundle.zip           # 热更新包（前端静态文件压缩包）
└── apk/                     # APK 下载目录（可选，用于整包更新）
    └── app-release.apk
```

**如果你的后端服务有专门的静态文件目录**（比如 `public/`、`static/`、`www/`），就把上面的 `appupdate/` 和 `apk/` 放进去。

### 3. 上传文件

把以下文件上传到服务器对应目录：

| 本地文件 | 上传到服务器路径 |
|---|---|
| `bundle.zip` | `静态根目录/appupdate/bundle.zip` |
| `manifest.json` | `静态根目录/appupdate/manifest.json` |
| `app-release.apk` | `静态根目录/apk/app-release.apk` |

### 4. 配置热更新 API（如果后端还没实现）

App 端会调用以下接口，你需要在后端实现：

#### 接口 1：检查更新

```
GET /api/appupdate/check?device_id=xxx&platform=android&native_version=1.0&current=builtin
```

响应格式（JSON）：

```json
{
  "success": true,
  "data": {
    "version": "1.0.0",
    "url": "bundle.zip",
    "minNativeVersion": "1.0"
  }
}
```

字段说明：
- `version`：热更新包版本号（比当前版本新才会更新）
- `url`：热更新包文件名（App 会从 `/appupdate/{url}` 下载）
- `minNativeVersion`：要求的最低原生 App 版本（可选，低于此版本不更新）

**如果不想写 API**，可以只用静态 `manifest.json`：App 在 API 不通时会自动回退到读取 `/appupdate/manifest.json`，格式如下：

```json
{
  "version": "1.0.0",
  "url": "bundle.zip",
  "minNativeVersion": "1.0"
}
```

#### 接口 2：事件上报（可选，不影响更新）

```
POST /api/appupdate/report
Content-Type: application/json

{
  "device_id": "xxx",
  "platform": "android",
  "event": "downloaded",
  "current": "builtin",
  "to_version": "1.0.0"
}
```

这个接口用于统计更新事件，可以简单返回 200 即可，不实现也不影响热更新功能。

## 三、验证方法

### 1. 验证文件可访问

在浏览器或 curl 中访问：

```bash
# 热更新清单
curl http://152.136.100.200:4000/appupdate/manifest.json

# 热更新包（应该能下载）
curl -I http://152.136.100.200:4000/appupdate/bundle.zip

# APK 下载
curl -I http://152.136.100.200:4000/apk/app-release.apk
```

### 2. 验证 App 端热更新

1. 手机安装 `app-release.apk`
2. 打开 App，App 启动时会自动检查更新
3. 如果 `manifest.json` 里的 version 比当前版本新，会自动下载并应用更新
4. 更新后 App 会自动刷新，运行新版本

## 四、日常更新流程（以后每次发版）

### 热更新（不重新安装 APK，只更新前端代码）

1. 修改前端代码，重新构建 `www/` 目录
2. 把 `www/` 目录里的所有文件打包成 `bundle.zip`
3. 修改 `manifest.json` 里的 `version` 为新版本号（比如 `1.0.1`）
4. 把 `bundle.zip` 和 `manifest.json` 上传到服务器 `/appupdate/` 目录，覆盖旧文件
5. 用户下次打开 App 时会自动检测并更新

### 整包更新（需要重新安装 APK）

1. 修改原生代码（Android/iOS 原生层）或需要升级最低原生版本时
2. 重新构建 APK
3. 上传到服务器 `/apk/` 目录
4. 在 App 内提示用户下载安装新版本

## 五、注意事项

1. **端口 4000 必须对外开放**：云服务器安全组/防火墙要放行 4000 端口入站
2. **热更新包是 zip 格式**：直接压缩 `www/` 目录里的**文件内容**（不是压缩 www 文件夹本身），解压后根目录就是 index.html
3. **版本号格式**：用 `x.y.z` 格式，比如 `1.0.0`、`1.0.1`，App 会按数字比较版本大小
4. **Android 已允许明文 HTTP**：App 端已配置 `usesCleartextTraffic="true"`，HTTP 可以正常使用
5. **iOS 端**：iOS 禁止明文 HTTP，需要自己用签名工具处理或配置 ATS 例外
